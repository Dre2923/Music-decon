## Resolved: bpm-detector shortcut (previously "Deviation notice" here)

An earlier version of `backend/audio_diagnostics/bpm_key_pitch.py` called `librosa.beat.beat_track` directly and used a self-written Krumhansl-Kessler key-correlation function, instead of the `bpm-detector` package the manifesto names. That was flagged in `docs/OPEN_ISSUES.md` (S1) as an unauthorized shortcut pending sign-off. The user explicitly rejected it and required the real, licensed dependency with no substitution.

**Resolution:** the actual `libraz/bpm-detector` project (MIT-licensed) was located, cloned at pinned commit `9e82ed544edd7f06a5459b8fa8fe539f20335df8`, reviewed, and vendored verbatim into `backend/audio_diagnostics/vendor/bpm-detector/` (see that directory's `NOTICE.md`). `bpm_key_pitch.py` now calls its real `BPMDetector` and `KeyDetector` classes directly. All of its runtime dependencies (rows above) were checked against installed-package license metadata and are permissively licensed and commercial-use compatible. S1 in `docs/OPEN_ISSUES.md` is marked resolved.

**Known consequence, not itself a shortcut:** using the real package's own `__init__.py` (unmodified) pulls in its full analysis suite and, with it, scikit-learn/matplotlib/seaborn/pandas/psutil as import-time dependencies even though this project only calls BPM and key detection. This is the actual, faithful dependency footprint of the named library, not something invented here — but it is heavier than the manifesto's "uses librosa internally" description implies and has not been benchmarked on the Raspberry Pi 5 backend. Tracked as a new open item in `docs/OPEN_ISSUES.md`.

## Process

1. Before adding a new third-party component to the codebase, add a row here first.
2. Before any milestone listed in Section 10.2 of the manifesto (beta, TestFlight, Play internal testing, Windows certification, production submission, vendor replacement), re-check every row's primary source and update "Date checked."
3. A blocked cell (weights, redistribution, etc.) is a release gate per manifesto Section 6/10.14 — code depending on a blocked artifact must not ship until the row is unblocked with a recorded source and date.
